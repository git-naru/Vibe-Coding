## PFD Flow Viewer (Claude Code skill)

`.claude/skills/pfd-flow-viewer/` — PFD 도면과 Mass Balance(PDF, XLSX, DOCX)를 읽어 계통별 인터랙티브 흐름도를 만드는 Claude Code 스킬입니다.

- 이 저장소에서 Claude Code를 열고 PFD 파일을 첨부한 뒤 "스팀 계통 흐름도 그려줘"처럼 요청하면 스킬이 적용됩니다.
- 실제 프로젝트 데이터는 공개 저장소에 커밋하지 않습니다.
- 결과 화면: 계통 흐름도, 라인 클릭 시 Stream Table(유량·물성·성분), 설비 클릭 시 입출구 비교, 일 기준 물질수지 검증, 시트 간 불일치 표시.

| 경로 | 내용 |
|---|---|
| `SKILL.md` | 작업 절차 (범위 → 읽기 → 정리 → 수지 검증 → 배치 → 빌드·게시 → 보고) |
| `assets/viewer-template.html` | 고정된 화면 템플릿 (라이트/다크, 모바일 대응) |
| `scripts/pfd_extract.py` | PDF(여러 파일·여러 장) 시트 식별, 시트 간 연결 지도, Stream 번호 검색, 고해상도 렌더·표 크롭, XLSX/DOCX 덤프 |
| `scripts/build_viewer.py` | 데이터 검증(참조, 좌표 겹침, 물질수지) 후 HTML 빌드 |
| `references/data-schema.md` | 데이터 JSON 형식과 Stream Table 항목 매핑 |
| `examples/demo-steam.json` | 가상 데이터 예제: 보일러 1기, 사용처 3곳의 스팀 계통 |

직접 빌드:

```bash
cd .claude/skills/pfd-flow-viewer
python3 scripts/build_viewer.py examples/demo-steam.json /tmp/demo.html
```

필요 도구: Python 3, poppler-utils(`pdftoppm`, `pdftotext`, `pdfinfo`), Pillow, openpyxl, python-docx.

## 공정 실적·투자비 (HTML 앱)

`apps/pfd-flow-viewer/` — PFD(Mass Balance 포함)로 공정 실적을 쌓고, 쌓인 실적으로 투자비를 산출하기 위한 단일 HTML 앱입니다(claude.ai Artifact로 게시).

- 시작 화면은 좌우 2분할입니다. 왼쪽 "실적 입력"은 실적을 쌓고, 오른쪽 "투자비 산출"은 쌓인 실적으로 설비비·공사비를 산출합니다.
- 실적 입력: 프로젝트(이름, 제품, 생산 능력, 위치, 기준 연도, 메모)를 만들고, 그 안에 PFD·P&ID·Mass Balance(PDF·XLSX·DOCX)를 올려 "흐름도 생성"을 누르면 흐름도·Equipment List·상세설명이 그 프로젝트의 실적 기록으로 자동 저장되어 누적됩니다. 기록은 다시 열 때 Claude를 부르지 않습니다. 저장소는 본인만 보이는 개인 저장소(`db`, `data/users/<id>`)이고, 큰 결과는 여러 문서로 나눠 저장합니다.
- 흐름도: 원료에서 제품까지의 메인 흐름(Main Stream)을 먼저 만들고, 적은 계통(예: 스팀·응축수)은 별도 탭으로 만듭니다. 결과 화면의 "탭 추가"로 계통 탭을 더 만들 수 있습니다.
- 흐름 보기: 흐름도 위에서 "패키지별"과 "설비별"을 고릅니다. 패키지는 함께 발주·공급되거나 한 단위 공정을 이루는 설비 묶음(투자비 산출 단위)으로, 생성 마지막 단계에서 Claude가 묶습니다. 패키지별 보기에서는 패키지 하나가 상자 하나이고 패키지 사이 Stream만 선으로 그리며, 패키지 안 Stream과 소속 설비는 상세설명 카드에 나옵니다(설비를 누르면 설비별 보기에서 그 설비로 이동). 패키지가 없는 결과는 "패키지 묶기"로 만들 수 있습니다.
- 상세설명: 흐름도 옆에 따로 스크롤되는 프레임으로 모든 설비와 라인의 카드를 보여줍니다(역할 설명, From/To, 유량·온도·압력, 유량·물성·성분 표, 연결 Stream). 흐름도에서 라인이나 설비를 누르면 프레임만 그 카드로 스크롤되고, 카드를 누르면 흐름도에 표시됩니다. 설비/라인 거르기와 찾기가 있습니다. 역할 설명은 생성 마지막 단계에서 Claude가 쓰고, 설명이 없는 결과는 "설명 작성"으로 만들 수 있습니다.
- 브라우저: 파일 읽기(pdf.js, SheetJS, mammoth; ToUnicode 없는 한글 CID 글꼴·KS 인코딩 PDF도 읽도록 pdf.js 한글 CMap을 화면에 넣음, 일본어·중국어 CID 글꼴은 아직 글자가 빠짐), 시트 식별·시트 간 연결, 텍스트·엑셀 표 값 채우기, 물질수지 검증, 자동 배치(dagre). 메인 흐름(또는 한 줄로 너무 긴 흐름)은 공정 구역(Tag·도면 번호의 4자리 구역)마다 한 줄로 흐름 순서대로 쌓고, 이웃 줄 사이 연결은 줄 사이 간격으로, 재순환·줄 건너뛰기 연결은 왼쪽 여백 통로로 그립니다.
- Claude(`sample` capability): 계통 범위 판단 1회, 시트별 연결 해석(도면 이미지 + 글자 위치), 표가 이미지인 시트의 표 판독, 설비·라인 설명 작성, 패키지 묶기. 판독값은 "이미지 판독값"으로 표시됩니다.
- Equipment List: PDF를 올리면 Claude 없이 자동으로 만듭니다(원형 진행률 0~100%). 설비 이름 아래 단독으로 적힌 Tag를 설비로 보고, 호기 번호 분리·예비/향후 구분·도면 구역(테두리 격자 행-열)을 붙입니다. Tag 없이 이름만 있는 설비는 "미확인" 후보로 넣습니다.
  - 표는 10행 높이로 스크롤되고, 행을 더블클릭(또는 Enter)하면 해당 PFD 쪽을 새 창에 열어 위치를 빨간 상자로 표시합니다(새 창이 막히면 화면 안 보기). 저장된 기록에는 원본 PDF가 없어 같은 PDF를 다시 올려야 열립니다.
  - 흐름도를 생성하거나 열면 그 계통 설비에 기준 Stream 값(유량·온도·압력)이 채워집니다.
  - "그림으로 설비 찾기"(F37): 글자 없이 기호로만 그려진 설비를 Claude가 도면 이미지(시트당 4조각, 1회 호출)로 찾아 "(그림)" 미확인 후보로 더합니다. 겹친 조각의 중복, Tag 글자 위치, 글자로 이미 찾은 후보는 걸러내고 신뢰도를 표시합니다. 중지 후 다시 누르면 남은 시트만 이어서 합니다.
  - 설비비 매칭: 사람이 관리하는 Equipment List(설비비 포함 Excel·CSV)를 "설비비 목록 올리기"로 올리거나 PFD와 함께 올리면(Stream 표가 아닌 엑셀은 자동 인식) PFD Equipment List와 매칭합니다. 머리글 행과 Tag·설비명·수량·단가·금액 열을 찾고, Tag(범위 001/002·001~003, A/B, 번호 자릿수·접두어 차이 정리) → 이름 유사 → "Claude로 남은 항목 매칭" 순으로 맞춥니다. 목록 1행이 여러 기를 가리키면 금액을 기수로 나눕니다. 남은 행은 PFD 설비를 직접 고르고, 표의 설비비 칸을 눌러 금액을 직접 입력할 수 있습니다. Equipment List 표에 설비별 설비비와 매칭 방법이 나오고, 수동 목록 총액 = PFD 매칭 + PFD에 없는 항목으로 맞춰 보여줍니다. 상세설명 카드에는 설비별 설비비와 패키지 설비비 합계가 나옵니다. 매칭 결과는 실적 기록에 함께 저장됩니다.
  - Layout·GA 도면: PFD·P&ID와 함께 Layout·GA·Plot Plan 도면 PDF를 올리면 Equipment List 위에 "Layout · GA" 카드가 나옵니다. `-PFD-`·`-PID-` 도면 번호나 공정 제목이 없고 표제란(또는 파일 이름)에 GENERAL ARRANGEMENT·PLOT PLAN·LAYOUT·배치도가 있으면 Layout으로 보고, 흐름도와 Equipment List 만들기에서는 뺍니다. 파일 목록의 "Layout으로"/"PFD로" 버튼으로 바꿀 수 있습니다. 도면 글자에서 찾은 Tag(Area 번호 없이 적은 `PU-001`도 목록에 하나뿐이면 인정)를 Equipment List와 Tag로 맞춰 파란 상자(목록에 있음)와 회색 점선(목록에 없음)으로 표시합니다. 상자를 누르면 선택되고(설비 정보, PFD 열기), 두 번 누르면 Equipment List의 그 행으로 이동합니다. 목록에서 행을 누르면 Layout에서 그 설비가 선택되고 확대됩니다(다른 장이면 그 장으로). Equipment List 표와 Excel에 Layout 열이 붙습니다. 도면 그림은 기록에 저장하지 않으므로, 저장된 기록을 연 뒤 같은 Layout PDF를 올리면 다시 맞춥니다(기록의 Equipment List는 그대로 둠).
  - "Excel로 내려받기"는 Equipment List(설비비 열 포함), Summary(Area별 설비비 합계), 도면 미포함 설비, 설비비 매칭(수동 목록 행별 매칭 결과), 작성 기준 시트의 .xlsx를 만듭니다.
- 공사물량(실적): 실적 프로젝트의 Equipment List 아래 "공사물량" 카드에 실제 공사물량을 넣습니다(목록 올리기: 대상 | 공종 | 물량 | 단위, 또는 한 줄씩 추가). 대상은 설비 Tag(범위 표기 가능, 여러 기면 나눔), 패키지 이름, 또는 "공통"(프로젝트 전체)입니다. 기록에 함께 저장됩니다.
- 투자비 산출(오른쪽 화면):
  - 공사 단가(회사 기준): 공종 | 단위 | 단가 표를 올리거나 직접 넣습니다. 공종 이름으로 실적 물량과 연결됩니다.
  - 산출 기준: 설비 종류별 용량 지수 n(기본값은 일반 문헌의 대략값, 회사 기준으로 수정)과 공사물량 지수.
  - 산출 프로젝트: "새 산출"로 만들고 실적 입력과 같은 방식으로 PFD를 올려 흐름도·Equipment List·패키지를 만들면 "투자비 산출" 카드가 계산합니다.
  - 설비비: 같은 종류의 실적 설비 중 용량(탱크류는 Nominal 용적 m³, 그 밖은 Design 유량 t/h)이 가장 가까운 설비를 골라 실적 설비비 × (용량비)^n. 같은 종류·단위 실적의 설비비/용량 중앙값 × 용량("실적 단가")도 함께 보여주고 설비마다 적용 방법(용량지수·실적 단가·제외)을 고르며, 용량과 설비비는 직접 고칠 수 있습니다.
  - 공사비: 학습 물량 × 공사 단가. 설비 기준 물량은 실적의 설비 종류·공종별 물량 / Σ(설비비^m)를 학습해 같은 종류 Σ(설비비^m)에 곱하고, 패키지 기준 물량은 이름이나 설비 구성이 비슷한 실적 패키지 물량 × (패키지 설비비 비)^m, 공통 물량은 실적의 (공통 물량 / 설비비 합계) × 이 프로젝트 설비비 합계입니다. 공종별 물량은 직접 고칠 수 있고 근거 줄이 남습니다.
  - "근거표 Excel": 요약, 설비비(유사 실적·용량비·지수·단가), 공사비, 공사물량 근거, 산출 기준 시트.
- 둘러보기: "예시 보기"(가상 데이터), JSON 파일 열기는 프로젝트에 저장되지 않는 보기입니다. 프로젝트 안의 "JSON 가져오기"는 스킬로 만든 데이터 JSON을 실적 기록으로 넣습니다.

```bash
python3 apps/pfd-flow-viewer/build.py /tmp/pfd-flow-app.html   # 예시 데이터를 넣어 단일 파일로 빌드
python3 apps/pfd-flow-viewer/build.py /tmp/pfd-flow-app.html --sample /path/sample.json   # 비공개 게시용: "실적 샘플 보기" 버튼에 실데이터 결과 포함
```

"실적 샘플"(실제 PFD로 만든 흐름도와 Equipment List)은 실데이터라 저장소에 두지 않고 비공개 게시본에만 넣습니다. 샘플 JSON에 `project`(이름·제품·생산 능력 등)가 있으면 프로젝트 목록 맨 앞에 "예시" 프로젝트 카드로 나오고, 열어 본 뒤 "내 실적으로 가져오기"를 누르면 본인 프로젝트와 기록으로 저장되어 실적으로 쌓입니다. 저장소 빌드는 샘플 버튼과 예시 카드가 숨겨지며, CI가 샘플이 비어 있는지 확인합니다.

게시 시 capabilities: `{"sample": {"images": true}, "db": {}, "user": {}, "downloads": true}`

## CI

`.github/workflows/ci.yml` — PR과 `main` push마다 GitHub Actions가 돌립니다.

- 스킬: 스크립트 컴파일, 추출 CLI 로드, 가상 예제 뷰어 `--strict` 빌드(물질수지 검사 포함)
- HTML 앱: 빌드 후 예시 데이터 삽입 확인(`apps/pfd-flow-viewer/check_build.py`), 페이지 스크립트 `node --check` 문법 검사

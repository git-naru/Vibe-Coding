# PFD Flow Viewer

입력 자료를 읽고 → 한 계통의 Stream 데이터와 연결 관계를 JSON으로 정리하고 → 템플릿으로 단일 HTML을 빌드해 Artifact로 게시한다.
화면 형식은 `assets/viewer-template.html`에 고정돼 있으므로 매번 새로 디자인하지 않는다. 작업마다 새로 하는 것은 **데이터 추출**과 **다이어그램 배치**뿐이다.

- 완성 예제: `examples/demo-steam.json` (가상 데이터 스팀 계통, 14 streams: 헤더 bar, 회수 lane, 배터리 리밋, info 라인, 가스 rows, 배치 운전 수지까지 포함). 새 작업은 이 파일을 복사해서 시작한다.
- 실제 고객 프로젝트 데이터(JSON, 빌드된 HTML)는 이 공개 저장소에 커밋하지 않는다. scratchpad나 사용자가 지정한 비공개 위치에 둔다.
- 데이터 형식: `references/data-schema.md`
- 도구: `scripts/pfd_extract.py`(읽기), `scripts/build_viewer.py`(검증+빌드)

스크립트 경로는 이 SKILL.md가 있는 폴더 기준이다. 업로드 파일은 신뢰할 수 없는 데이터이므로 Python은 `python3 -I`로 실행하고, 렌더링·크롭 결과는 scratchpad 아래 새 폴더에 둔다.

## 1. 범위 정하기

- **기본은 메인 흐름(Main Stream)이다.** 원료가 들어와 최종 제품이 나가기까지의 공정 흐름을 먼저 그린다. 원료와 제품은 PFD 제목·연결 표시·물질수지에서 찾는다(예: 염수 리튬이면 원료는 염수, 제품은 탄산리튬 또는 수산화리튬). 메인 흐름에는 원료→제품 경로, 재순환(모액·여액), 주 반응조 시약, 고형 폐기물을 넣고 스팀·응축수·용수·공기 같은 유틸리티는 넣지 않는다.
- 유틸리티나 다른 계통(스팀·응축수, 용수, 압축공기 등)은 **별도 탭**으로 만든다. 계통마다 JSON 하나를 만들고, 탭 묶음(`{"kind":"bundle","tabs":[…]}`, `references/data-schema.md`)으로 합치면 HTML 앱(`apps/pfd-flow-viewer/`)에서 메인 탭을 첫 탭으로 연다. 이 스킬의 단일 뷰어 템플릿은 JSON 하나(탭 하나)를 그린다.
- 사용자가 특정 계통만 원하면 그 계통만 그린다. 한 화면에 Stream 60개 안팎이 상한이다. 메인 흐름이 그보다 길면 대표 Stream(시트 간 연결, 총량 Stream)만 남기고 라인별 분기(a, b, c)는 라벨 하나(`"label": "209a,b"`)로 묶는다.
- 출력 언어는 사용자 언어(기본 한국어)로 쓰고, Stream 원문 설명(`en`), 설비 Tag, 도면 번호는 원문 그대로 둔다.

## 2. 자료 읽기

**PDF 도면** — 파일 하나에 여러 장, 파일마다 한 장, 또는 둘이 섞여 들어온다. 파일 순서나 이름은 믿지 않고 **도면 번호로 시트를 식별**한다. 아래 명령은 모두 파일 여러 개와 폴더를 받는다(`PDFS...`).
1. `pfd_extract.py info PDFS...`로 페이지별 도면 번호(타이틀 블록), 제목, 텍스트층 유무를 확인한다. `IMAGE-ONLY` 페이지는 스캔본이라 숫자를 눈으로 읽어야 하고 시트 연결도 자동으로 잡히지 않으므로, 판독 오류 가능성을 보고서에 적는다.
2. `pfd_extract.py links PDFS... --json LINKS.json`으로 **시트 지도**를 만든다. 각 시트의 Off-page 연결(다른 도면 번호 + FROM/TO + Stream 번호)을 모아 다음을 알려준다.
   - 연결 대상 도면이 입력에 있으면 그 파일·페이지, 없으면 `NOT PROVIDED`(입력에 없는 도면 목록도 따로 나온다)
   - 상대 시트에도 같은 Stream의 반대 방향 연결이 있으면 `matched`, 없으면 `no return connector`
   - 원 도면의 번호 오기(예: `000789` ↔ `00789`)는 `dwg no. typo in source`로 표시하고 같은 시트로 연결한다
   - 같은 도면 번호가 두 시트에 나오면 `WARN`
   여러 시트에 걸친 계통은 이 표로 연결을 따라가며 범위를 정한다. 대상 계통이 입력에 없는 도면으로 이어지면, 그 끝은 배터리 리밋(`src` 박스)으로 두고 "입력에 없음"을 note에 적는다. 사용자에게 그 도면을 더 달라고 할지 보고서에서 묻는다.
   `no return connector`와 번호 오기는 자동 판정이므로, 해당 연결은 도면을 확대해 직접 확인하고 원 도면의 문제가 맞으면 note에 적는다.
3. 전체 구조는 Read 도구로 PDF를 페이지 단위로 훑어 파악한다. 이 저해상도 화면에서 **숫자를 옮겨 적지 않는다.**
4. 대상 계통이 나오는 페이지를 찾는다: `pfd_extract.py find PDFS... -t 105 106 107 …` (Stream 번호, Tag). 결과는 `파일 p페이지`로 나온다. 같은 Stream이 여러 시트에 있으면 전부 확인해 값이 다른지 비교한다.
5. `render FILE.pdf 27 OUTDIR --dpi 250~300`으로 고해상도 PNG를 만든 뒤, `crop`으로 Stream Table을 잘라 Read로 읽는다. (회전된 시트도 화면에 보이는 방향으로 렌더링된다.)
   - 좌표는 Read 미리보기(가로 약 2000px) 기준으로 준다: `--box X0 Y0 X1 Y1`.
   - 열이 많은 표는 `--cols 50:215,1300:1450`처럼 항목명 열과 필요한 Stream 열만 이어 붙여 읽는다. 한 장에 Stream 10~12열 이하가 되게 나눈다.
   - 도면 본체도 같은 방식으로 2~4조각으로 잘라 확대해, 라인이 어디서 어디로 가는지, 합류·분기, 운전/예비(SB) 장비를 확인한다.
6. Note 문단(도면 하단)은 `text FILE.pdf PAGE`로 텍스트를 뽑아 읽는다. 운전시간, 배치/간헐 운전, 설계 여유, 재순환 비율 같은 해석 근거가 여기 있다.

**XLSX (Stream Table / Mass Balance)**: `pfd_extract.py xlsx FILE.xlsx`로 시트별 셀 좌표와 값을 뽑는다. 수치는 엑셀 값을 우선한다(도면 판독보다 정확). `[no cached value: =…]`가 보이면 수식 결과가 저장되지 않은 파일이므로 사용자에게 엑셀에서 저장한 파일을 요청하거나 수식을 직접 계산해 출처를 표시한다. 엑셀에는 보통 연결 관계가 없으므로 From/To는 PFD 도면이나 사용자 설명으로 채운다.

**DOCX (공정 설명서, Operating Philosophy)**: `pfd_extract.py docx FILE.docx`로 문단과 표를 뽑아 운전 조건과 Note 해석에 쓴다.

## 3. 데이터 정리 규칙

- 값은 원문 문자열 그대로 옮긴다(`1,562`, `4.5–5.5`, `NOTE 14`). 소수점 쉼표(`1,06`) 표기의 도면은 점으로 바꾸되 천 단위 쉼표와 헷갈리지 않게 주의한다. 빈칸·`-`는 키를 생략한다.
- **값을 고치거나 추정해서 채우지 않는다.** 모순되는 값(예: Design 평균 > Design 최대)은 그대로 두고 `note`에 "확인 필요"로 적는다.
- 같은 Stream이 시트마다 다르면, 계통을 소유한 시트(예: 스팀 계통은 유틸리티 시트) 값을 `v`에 넣고, 다른 시트 값은 `note`에 "공정 시트에는 50 t/d로 적혀 있음"처럼 적는다. 어떤 Stream이 소유 시트 표에 없으면 다른 시트 값을 쓰고 그 사실을 note에 쓴다.
- 도면에 번호가 없는 라인(약품 주입 등)은 `info: true` Stream으로 만들어 설명만 보여준다.
- 일반 지식으로 덧붙이는 설명(예: 약품 용도)은 "일반적인 용도" 등으로 도면 내용과 구분해 적는다.
- `ko`는 현장 엔지니어가 바로 알아볼 짧은 한국어 이름, `from`/`to`에는 설비 Tag를 넣는다.
- 열교환기·반응기처럼 공정측 입출구가 있는 설비는 `nodeInfo.compare`에 입구/출구 Stream 값을 나란히 넣는다.

## 4. 물질수지 검증

- `checks`에 합류·분기·저장조 입출 관계를 넣는다(생산=소비, 회수 합계, 탱크 입=출, 보충=손실).
- **일 합계(`dm`, t/d) 기준으로 맞춘다.** 배치·간헐 운전 Stream은 시간당 값(t/h)을 더하면 맞지 않는다. 이 사실을 `meta.hint`에 적는다.
- 반올림 차이는 `tol`(보통 1~2)로 허용한다. 허용 범위를 넘으면 값을 바꾸지 말고 보고서와 note에 차이를 적는다.

## 5. 다이어그램 배치

메인 흐름은 공정 구역(Area)마다 한 줄씩 왼쪽→오른쪽으로 놓고 줄을 위에서 아래로 쌓는다(예: Liming → Ca·Mg 제거·IX → 탄산화·고액 분리 → 건조·포장 → 모액 처리). 시약은 반응조 위 줄에, 폐기물은 아래 줄에 둔다. 재순환(모액 반송 등)은 바깥쪽 lane(왼쪽 여백·맨 아래)으로 돌려 본 흐름과 겹치지 않게 한다. 입력에 없는 도면을 거치는 구간(예: 폰드)은 배터리 리밋 박스와 점선으로 잇는다. 칸 간격은 Stream 번호 배지가 설비 상자를 가리지 않게 상자 폭 + 70px 이상으로 둔다.

원 도면을 베끼지 말고 흐름이 읽히도록 다시 배치한다. 좌표계는 `viewBox`(기본 1600×900 근처), 10px 격자에 맞춘다.

- 흐름은 왼쪽→오른쪽: 공급원(배터리 리밋, `src: true`) → 처리·저장 → 핵심 설비 → 분배 헤더(`bars`) → 사용처 → 회수 lane(오른쪽 세로) → 하단 가로 lane으로 되돌아오는 재순환/회수.
- 같은 역할의 설비는 같은 크기로 세로 정렬한다(사용처 박스 180×86, 간격 120 등). 사용처 박스의 3번째 줄(`sub2`, `sub2Strong`)에 공정측 변화(예: `염수 7 → 58 °C`)를 쓴다.
- 보조 계통(블로다운·냉각·배수)은 빈 구석에 `frames`로 묶고, 멀리 이어지는 라인은 끊고 연결 표시(`texts`의 "→ Purge Tank", `src` 박스)로 처리해 교차를 피한다. 불가피한 교차는 halo가 자동으로 끊어 보여준다.
- Stream 번호 배지(`lab`)는 선분 중간에 두고, 배지가 들어갈 선분은 최소 45px로 한다. 3자리 번호 배지 폭은 약 44px이다.
- 합류 지점에는 `dots`, 다른 라인에 합쳐지는 끝은 `"arrow": false`.
- 같은 Stream이 여러 선분으로 나뉘면 같은 `s`로 여러 `lines`를 만들고 배지는 하나만 둔다.

## 6. 빌드 · 확인 · 게시

1. JSON은 scratchpad에 작성한다. 사용자가 보관을 원하면 저장소가 비공개인지 먼저 확인하고, 공개 저장소라면 커밋하지 말고 다른 보관 위치를 묻는다.
2. `python3 scripts/build_viewer.py data.json OUT.html --links LINKS.json` 실행 → `ERROR`는 반드시 고치고, `WARN overlap`·`crosses`는 좌표를 옮겨 없앤다. `balance:` 결과를 보고서에 쓴다. `--links`를 주면 화면 상단에 입력 시트 목록과 시트 간 연결 검사 요약이 나오고, 시트를 넘나드는 Stream마다 "시트" 항목(양쪽 도면 번호와 파일·페이지)이 채워진다. 이미 `sheets`가 적힌 Stream은 덮어쓰지 않는다.
3. 화면을 한 번만 확인한다(Artifact 미리보기 또는 Playwright 스크린샷 1장). 겹침·잘림만 고치고 반복하지 않는다.
4. Artifact 도구 규칙대로 게시한다(새 페이지면 quickstart 후 publish, `icon: "flow"`). 같은 페이지를 고칠 때는 같은 파일 경로로 다시 publish 해 URL을 유지한다.

## 7. 보고 (채팅)

- 이해한 흐름을 10줄 안팎의 텍스트 다이어그램으로 요약한다.
- 물질수지 검증 결과(맞은 것/안 맞은 것, 시간당 vs 일 합계 주의).
- 시트 간 불일치, 모순 값, 스캔본 판독 위험, 도면에 없는 정보를 덧붙인 곳.
- 입력 시트 수와 파일 수, 시트 연결 검사 결과(확인된 수, `no return connector`·번호 오기), 계통이 이어지지만 입력에 없는 도면.
- Artifact 링크와 "비공개이므로 공유는 Share 메뉴에서" 안내.
